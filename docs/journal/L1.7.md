# L1.7: Voices, polyphony & the Engine (CFS) ★ M2
*Date started / finished:* 2026-11-17 / 2026-11-17  ·  *Built by:* Claude

## Goal
Chords, and `fss_core`'s real public API: `fss::Event`, `fss::Engine` (`prepare / reset / setPatch /
process(events, L, R, n)`), a voice pool with allocation and stealing (D8), sample-accurate event handling,
and the block-size invariance test.

## Predictions (before building)
- If every per-sample computation lives inside voices, and events are applied at their exact frame,
  output is *bit-identical* for any block size. Any difference means hidden per-block state.
- Hard-cut steals of a pure sine click above L1.1's bare-sine reference (−43.7 dB above 2–3 kHz); 5 ms
  fades bring them down to the level of a short envelope attack.

## What actually happened
- **Block-size invariance:** blocks of 1, 64, 333 and 4096 samples render a 2 s random score (120 notes, bends,
  feedback, polyphony 6 → constant stealing) **bit-identically** (`memcmp`). Passed on the first run.
- **Tests** 71/71 (6 new): invariance, a note starts on exactly its frame, voices freed after release and never
  over the limit (10 notes into 4 voices → 6 steals → 4 busy once the fades end), victim choice (released before
  held), same-key re-strike (2 voices briefly, 0 steals), soft clip (transparent ≤ 0.8, bounded, continuous slope).
- **The piece** (`l1.7_piece.wav`, 22 s, 256-sample blocks): e-piano chords + melody in one Engine (max 8 busy
  voices, 0 steals) + FM bass in a second; peak 0.73, nothing clipped.
- **Stealing stress** (48 notes 25 ms apart into 8 voices, 40 steals; energy above 3 kHz per 2.7 ms frame):

| | worst frame | frames > −60 dB |
|---|---|---|
| 5 ms fade | **−51.4 dB** | 30 (also includes 48 note attacks at ≈ −60 dB) |
| hard cut | −37.5 dB | 111 |

**Exit criteria (M2):** a short piece rendered by the engine ✅ (whether it's one to be *proud of* is the
owner's ear to judge; it's musically simple on purpose: Am–F–C–G); block-size invariance passes ✅;
stealing click-free in a stress render ✅ (worst steal below the bare-sine reference; the hard-cut version shows what's avoided).

## How it works
```
Engine::process(events, L, R, n):   pos = 0
    for e in events:  render(pos, e.frame); handle(e); pos = e.frame
    render(pos, n)
handle(NoteOn):  same key sounding → fade it (re-strike)
                 sounding ≥ polyphony → victim = oldest released, else oldest held → fade it (5 ms)
                 start the note in a free slot (16 + 4 headroom slots), never delayed
render(a, b):    zero; for each busy voice: add voice.tick() for a..b; × outputGain; softClip; copy to R
```
The patch is *copied* into the Engine; voices point at that copy (so `setBend` can recompute frequencies).
`fss_core` became a STATIC library: `core/src/engine.cpp` is its first .cpp.

## Alternatives rejected
- **Release-then-start in the stolen slot.** Simple, but the new note waits for the fade (5 ms of latency
  on exactly the busiest passages). Four spare slots cost 20 % more voice *memory*, and no extra CPU for
  silent slots.
- **Quietest-voice stealing.** Often better musically, but needs a running level estimate per voice.
  Released-then-oldest is a good proxy (released voices *are* the quiet ones). Revisit in L2.5.
- **Restart a same-key voice in place.** Operators reset phase on note-on (key sync, L1.4), so a restart
  mid-waveform is a discontinuity: a click. A re-strike in a fresh slot is cleaner and sounds like a piano.
- **Per-block (not per-sample) event handling.** Simpler loop, but timing would depend on the host's
  block size: a 1024-sample block would quantize note starts to 21 ms. Sample-accurate is the CLAP model anyway.
- **A hard clipper on the output.** A soft clip with a tanh knee above 0.8 keeps accidental overloads
  musical. It's a safety net, not a sound (a real limiter comes in L5.6).

## What surprised me
1. **Invariance passed first time.** It shouldn't be taken for granted. The design choices that made it hold:
   voices ticked in a fixed order, no per-block smoothing or coefficient updates, events applied at exact frames.
   L2.4's parameter smoothing will be the first real threat to it.
2. **`std::tanh(large)` is exactly 1.0f** in float, so "the soft clip never reaches ±1" was false in practice.
   The test caught my claim; it now says "never exceeds".
3. Even a 5 ms fade of a pure sine leaves a measurable transient (−51 dB). It's comparable to a 2 ms attack.
   Zero is impossible; "below an envelope's own attack" is the honest bar.

## [THINK] answers
- **Why is same-key retrigger a separate case?** Because the "obvious" handling (reuse the voice playing
  that key) is wrong in two ways: it would restart the waveform mid-cycle (click), and musically a repeated
  piano key *re-strikes* while the old vibration is still dying. So CFS fades the old voice and starts a new
  one, and that doesn't count as a polyphony steal.
- **Free voices when *which* envelope goes idle?** When all *carrier* envelopes are idle (`FmVoice::isActive`).
  Modulators are inaudible on their own; waiting for a long modulator release would hold voices for
  nothing. (In a subtractive voice it would be the amp envelope.)

## Decisions made
- **D8** (decided): 16 + 4 headroom voices; steal released-oldest, then held-oldest; 5 ms fade in place; same-key re-strike.
