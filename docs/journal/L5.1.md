# L5.1: FX architecture: the chain, dry/wet, tails (CFS)
*Date started / finished:* 2026-11-18 / 2026-11-18  ·  *Built by:* Claude

## Goal
Decide how effects plug together (D16) before writing five of them: a global stereo FX chain after the voice
sum, with click-free on/off switching, tails that survive bypass, and two trivial effects (gain, stereo width)
to prove it.

## Predictions
*(An honest note: I wrote these after the code compiled but before rendering or timing anything. From L5.3
on they come before the code.)*
1. **Dispatch cost:** a virtual call per effect per block costs **under 1 %** at 64-sample blocks: the effect's
   per-sample loop is ~64× more work than one indirect call. So D16 won't be decided by speed.
2. **Bit-exactness:** moving the Output gain out of the voice loop into the chain's last stage changes **no
   output bit** (same multiply, same order), so `l1.7_piece.wav` stays `93d602f0…`.
3. **Clicks:** an instant width switch (0 % ↔ off) on a 220/330 Hz stereo tone shows a broadband burst; the
   10 ms linear fade puts the energy above 2 kHz **at least 30 dB lower**.
4. **Width on CFS today does nothing**, because the voices are mono (S = 0). The Engine test can only prove it's
   wired.

## What actually happened
1. **Dispatch: right.** `fss_render l5.1`, three slots (width, gain, width), 20 s of audio, Release:

   | block | tuple (static) | virtual | difference |
   |---|---|---|---|
   | 16 | 11.46 ns/sample | 11.84 | +3.3 % |
   | 64 | 12.81 | 13.13 | +2.5 % |
   | 256 | 13.15 | 13.10 | −0.4 % |

   A little more than predicted at small blocks, still noise (re-runs move these by ±2 %). D16 was decided on
   design grounds (below).
2. **Bit-exact: right.** `l1.7_piece.wav` SHA-256 `93d602f0…`, unchanged.
3. **Clicks: right, with a measuring surprise.** `click_meter.py --channel 0 --at 1 --at 2 --at 3`:
   fade **−101.8 dB**, hard switch **−63.7 dB** above 2 kHz: 38 dB less. The surprise: the first measurement
   said both were −110 dB, because the meter averaged L and R, and a mid/side change leaves L + R untouched
   (that's the definition of mid). The meter now has `--channel`.
   The e-piano with a −12 dB Gain slot toggled every 0.5 s (`l5.1_gain_toggle.wav`): the toggles at 0.5 s and
   1.5 s measure −92.8 / −105.7 dB; the 1 s / 2 s windows (−42 / −39 dB) are the chords' own attacks.
4. **Width: as predicted**, a no-op on today's mono voices (the Engine test: max difference 0, L = R).
5. **Tests 171/171** in Debug and Release (9 new: mix laws, width law, slot fades, spill + sleep, wake, slot
   and chain block-size invariance with random switches, chain pass-through, Engine wiring, `clap.tail`).
   The Engine's invariance test now compares both channels. Real-time audit: 0 allocations (the Debug DLL with
   the trap, via `fss_clap_host`). clap-validator 34/34. Editor: 84/84 parameters have a control, on 2 pages.

**Exit criterion:** chain framework plus two effects, with click-free toggling, tested by render ✅
(`renders/l5.1/`, numbers above) and by unit tests (no step larger than the ramp's 1/480 per sample).

## How it works
```
Engine::render(from, to):
  voices ─sum─► L = R = sum ─► FxChain::process ──────────────────────────────► softClip ─► out
                               │ FxSlot<StereoWidth> │ (later: drive, chorus, delay, reverb, EQ) │ Gain (Output) │
```
- **`fx/effect.h`**: `StereoBlock`, the `StereoEffect` concept, the dry/wet laws, and `FxSlot<E>`.
  The slot is the interesting part. It ramps a gain g over 10 ms when switched, per sample, and applies it
  according to the effect's `kSpillsTail`:
  - *crossfade*: `out = (1−g)·in + g·fx(in)`: off means dry, at once (after the fade).
  - *spill*: `out = (1−g)·in + fx(g·in)`: off means the effect gets no more input, but what it's already
    holding (echoes, reverb) keeps coming out. Same formula family; g just moves from after the effect to before.
  - *sleep*: a crossfade effect sleeps from the sample where g hits 0; an effect with a tail sleeps once its
    input has been exact silence for `tailSamples()`. Asleep = reset and not called; its output counts as zero.
    It wakes on the first sample that needs it. These decisions are per sample, so a host's block size can't
    change the result (the invariance test switches things at random samples and compares blocks of 1, 7, 64,
    1000 bit for bit).
- **`fx/width.h`**, **`fx/gain.h`**: the two trivial effects (mid/side scaling; a smoothed dB gain).
- **`fx/fx_chain.h`**: a `std::tuple` of slots plus the output `Gain`, visited with fold expressions. Splits
  long stretches into `maxBlock` pieces (the slot's scratch size). Reports `tailSamples()` (serial tails add)
  and `ringing()` (an effect with a tail is still awake).
- **Engine**: `prepare()` allocates the chain (so it's no longer `noexcept`; the plugin's `activate` catches
  `bad_alloc`); `render()` writes the voice sum to both channels, runs the chain on the same stretch, then the
  soft clip. New `ParamTarget::Fx`.
- **Parameters**: 200 `Width on`, 201 `Width` (%), group "Width". Ids 200–299 are the FX hundred, ten per effect.
- **CLAP**: a `clap.tail` extension (the tail from an atomic the audio thread updates; `host_tail.changed()`
  when it changes), and `CLAP_PROCESS_SLEEP` now also waits for `!fxRinging()`, because a delay's next echo
  can follow many blocks of exact silence.
- **Editor**: pages ("Synth", "FX"); the FX page draws one panel per FX group of the param table, in table
  order (= chain order), so new effects appear without editor code. `fss_play` lists them automatically (its
  UI is generated from the table's groups). Test host: `--snapshot file.bmp --page 1`.

## Alternatives rejected
- **Virtual `Effect` base + pointer array**: measured +0 to 3 % (above). Rejected not for speed but because its
  main benefit, run-time reordering, is something I decided not to offer (D16).
- **`std::variant` slots + `std::visit`**: the right tool for reorderable slots without heap; same reason.
- **The slot mixing dry/wet for every effect**: tempting (one mix knob implementation), but the right mix law
  differs per effect (linear for a chorus, equal power for a reverb), and spill-mode bypass needs the effect to
  own its wet path anyway. So effects own their mix; the slot owns only on/off.
- **Bypass by crossfading everything to dry** (simple, click-free): it cuts a delay's echoes 10 ms after you
  press the button. Spill is what hardware does and what players expect.
- **Deciding sleep per block** ("this whole block is silent, skip it"): cheaper bookkeeping, but then *when*
  an effect resets depends on the host's block size, and the invariance test fails.
- **A tab bar (ImGui `BeginTabBar`) for the editor pages**: its selection lives inside ImGui, so tests and the
  test host couldn't pick a page directly. Plain buttons + `EditorState::page`.

## What surprised me
1. **The mono-mix blind spot** in my own click meter (above). A stereo effect needs stereo measurement.
2. **CLAP sleep vs. echoes.** The L3.2 rule "sleep when the block is exactly zero and no voice is busy" would
   have silently eaten delay echoes: a 500 ms delay produces ~90 exact-zero blocks before its first repeat.
   It would never show up in a test that only plays notes back to back.
3. **Width is useless until something makes stereo.** Obvious in hindsight; it's why it sits last in the chain.

- **Bypass:** when you switch your delay off, do the echoes stop or ring out? Is your bypass a fade or a jump?
- **Sleep:** does your idle reverb still cost CPU? And if it sleeps, does that change with the host's block size?

- **Mix law:** which did you choose for which effect? Put a 50 % mix on a chorus with each law and listen to
  the level.

## Decisions made
- **D16:** fixed-order chain, effects by value in a `std::tuple`, a `StereoEffect` concept as the interface,
  a generic `FxSlot` for switching/spill/sleep; effects own their dry/wet. Full entry in DECISIONS.md.

## Open questions / for later
- Latency reporting (`clap.latency`) waits for the first effect that adds latency (oversampled drive, L5.2).
- A hard ceiling for runaway feedback: the soft clip bounds the output at ±1, but L5.6's limiter is the real
  safety net.
