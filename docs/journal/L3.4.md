# L3.4: State, presets & versioning (CFS)
*Date started / finished:* 2026-11-18 / 2026-11-18  ·  *Built by:* Claude

## Goal
A preset/state format that survives time: versioned, validated, readable (D15). The plugin saves it into
FL Studio projects (and still loads the L3.2 binary state already in projects), the factory bank exists as
files, and fss_play can browse, load and save presets.

## Predictions (before building)
1. **Size and speed:** a text patch is **~3 KB** (56 parameters, one commented line each) and writing or
   parsing one takes **under 50 µs**, so a text format costs nothing that matters (it runs on the main
   thread, at human speed).
2. **Exact round trip:** with `std::to_chars` shortest-form floats, `load(save(p))` gives every
   parameter's *bit-identical* float, and `save(load(save(p))) == save(p)` byte for byte, for random patches.
   The one place I expect trouble is **Output**, stored in the Patch as linear gain but as dB in the
   parameter table: dB → gain → dB may not return the same float.
3. **Fuzzing:** random bytes are rejected at the first check (binary characters); mutated *valid* files
   are mostly rejected (a flipped digit can still parse, and that's fine: it's a valid file with another value).
   No input crashes the parser or makes it read out of bounds.
4. **The four new presets** (bell, brass, organ, marimba) come out between **−12 and −3 dBFS peak** on their
   phrases with output gains picked by reasoning (carrier count, envelope shapes) before measuring.

## What actually happened
1. **Size and speed: right.** 3317–3346 bytes per patch (82 parameters, not the 56 I wrote above: that was
   the L2.4 count, before the filter, LFOs and voice modes); `patchToText` **19 µs**, `patchFromText` **9.8 µs**
   (`fss_render l3.4`, Release). Saving a project's CFS state is invisible next to anything a DAW does.
2. **Round trip: right, including the trouble spot.** 499 of 500 random patches came back bit-exact; the
   500th differed in **Output**, exactly as predicted. It isn't fixable inside the conversion: near 0 dB
   there are *more distinct dB floats than gain floats*, so a Patch that stores linear gain cannot hold
   every dB value a file can contain. **Fix: the Patch now stores `outputDb`** (the param table's unit), and
   the Engine converts with `dbToGain` where it needs a gain. New rule, written in `patch.h`: *a Patch stores
   every parameter in the param table's own unit.* After the fix: 500/500 exact, and save → load → save is
   byte-identical.
   **Side effect (intended, but it changes bits):** the e-piano's gain 0.22 survives the dB detour
   exactly, the FM bass's 0.45 doesn't. No float maps back to exactly 0.45f through this `pow` (I searched
   ±64 floats), so the bass in the L1.7 piece is now **7e-8 quieter (≈ −143 dB)**.
   **`l1.7_piece.wav` is now `93d602f0…`** (was `92baa60b…`). Inaudible by ~120 dB, but the bits changed,
   so this is the new golden hash.
3. **Fuzzing: right.** 20 000 inputs (noise, noise behind a valid header, valid files with 1–6 characters
   replaced/inserted/deleted): no crash, and every accepted patch is finite and in range. The plugin's
   v0 loader got the same treatment (5000 mutated binary states).
4. **Levels: half right.** Bell −4.4 dBFS ✅, marimba −9.3 ✅ (in range, but quiet: RMS −30.6), brass **−1.7**
   and organ **−2.3** ❌ (too hot: brass reached the soft clip's knee at 0.8). Re-levelled by measurement:
   brass 0.35 → 0.25 (−4.6 dBFS), organ 0.4 → 0.28 (−5.4), marimba 0.4 → 0.6 (−5.7). The whole bank now sits
   between −2.7 and −8.7 dBFS peak on its phrases:

   | preset | peak dBFS | RMS dBFS | | preset | peak dBFS | RMS dBFS |
   |---|---|---|---|---|---|---|
   | E-piano | −7.8 | −26.6 | | Legato bass | −4.8 | −16.2 |
   | FM bass | −5.3 | −17.5 | | Bell | −4.4 | −23.2 |
   | Reso pluck | −3.9 | −17.4 | | Brass | −4.6 | −16.9 |
   | Wobble bass | −2.7 | −17.0 | | Organ | −5.4 | −17.6 |
   | FM pad | −8.7 | −22.2 | | Marimba | −5.7 | −27.0 |

5. **A bug the L3.2 test host found:** "truncated state rejected" failed as soon as the state became text. A
   text file cut 3 bytes short still parses: it just loses the end of its last line. Binary had a size
   field; text had nothing. **Fix: a required last line `end`.** A file cut off while saving (crash, full
   disk) is now rejected instead of loading with its last parameters silently at defaults.
6. **Old projects still load:** a hand-written `CFS0` fixture (the bytes an FL Studio project saved with the
   L3.2 build contains) loads, its two parameters set and everything else at defaults, and the next save
   writes the text format: the project upgrades itself.
7. **Tests 159/159** in Debug and Release (13 new: 9 format, 1 preset library, 3 plugin state). Real-time
   audit 0 allocations; clap-validator still 34/34 (its binary reproducibility test passes with text).

**Exit criteria.**
- Round-trip and old-version tests pass; corrupted input rejected gracefully ✅.
- Ten presets ✅: `presets/factory/01..10 *.cfspatch` (six from L1.5–L2.5, four new) plus `00 Init`.
  **Whether they're good: for the owner's ears** (`renders/l3.4/*.wav`, or the preset menu in fss_play).

## How it works
- **`core/include/fss/synth/patch_io.h` + `core/src/patch_io.cpp`**: `patchToText` / `patchFromText`. Header
  `CFS patch 1`, `name = ...`, one `<id> = <value>  # name [unit] (label)` line per parameter, `end`. Rules:
  stable ids as keys, plain values, shortest exact floats, missing = default, unknown = skipped and counted,
  out of range = clamped and counted, anything malformed = the whole file rejected with its line number.
  `migrate()` is the (empty) hook for the day an id has to change meaning.
- **Versioning in one sentence:** *ids never change meaning*, so old files only lack ids (defaults fill
  them) and new files only add ids (skipped), and the format version only has to change if that promise is
  ever broken. Version 0 is the L3.2 binary state, which only the plugin reads (`hosts/clap/state_v0.*`).
- **Factory bank:** `presets/factory/*.cfspatch`, written from `presets.h` by `fss_render l3.4`, embedded
  into fss_core at configure time (`core/CMakeLists.txt` → `factory_bank.cpp`; re-configures when a file
  changes). A test checks the files and the code presets agree parameter for parameter.
- **`hosts/presets/preset_library.*`**: factory bank + `Documents\CFS Presets\*.cfspatch` (UTF-8 names,
  write-to-temp-then-rename saves, `CFS_PRESET_DIR` override for tests). fss_play has a preset menu,
  Rescan, a name field and Save. The plugin editor gets the same in L3.5.
- **Plugin state** = the same text as a preset file. `state.load` sniffs `CFS0` for old projects.

## Alternatives rejected (D15)
- **Binary** (the v0 format, or a versioned TLV): compact and fast, but undiffable, uneditable, and every
  field's byte layout becomes a promise. At 3 KB and 10 µs, text costs nothing.
- **JSON**: the obvious text choice, but it needs a parser (a library download, or a hand-written one twice
  the size of ours) for no gain: a patch is a flat list of numbers. A line format is trivially greppable and
  diffs one parameter per line.
- **Keys by name** ("cutoff = 2000"): friendlier to read, but names change (L1.10 renamed CC mappings,
  "Op A Ratio" vs "Ratio"); ids don't. The name is in the comment instead.
- **Normalized values in files**: they'd change meaning when a range changes. Plain values don't.
- **A checksum** to detect corruption: catches more than `end`, but breaks every hand edit. `end` catches
  the common failure (truncation) and costs nothing.
- **Lenient loading** (skip bad lines, load the rest): a preset that half-loads sounds wrong with no error.
  Rejecting with a line number tells the user exactly what to fix.

## What surprised me
1. **The format exposed a storage bug in the Patch.** I expected dB ↔ gain to be a rounding nuisance; it's
   a counting argument (more dB floats than gain floats near 0 dB). The real fix was upstream of the format.
2. **Text is truncation-tolerant**, which is a weakness, not a strength, for saved state. The old test that
   caught it was written for binary.
3. **Two of four presets came out too hot** despite reasoning about carriers: the brass's feedback and
   index swell add energy that "1 carrier at level 1" doesn't account for. Measure, don't estimate.

## Decisions made
- **D15:** versioned line-based text, keys = stable param ids, plain shortest-exact values, `end` line,
  strict rejection; plugin state = the same text; v0 binary still loaded. Full entry in DECISIONS.md.
