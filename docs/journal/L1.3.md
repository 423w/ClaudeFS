# L1.3: Envelopes: ADSR as a state machine (CFS)
*Date started / finished:* 2026-11-17 / 2026-11-17  ·  *Built by:* Claude

## Goal
Give sound a shape over time and remove the clicks found in L1.1: `fss::dsp::Adsr`, decided as D6.

## Predictions (before building)
- **Minimum attack time** (numpy, 440 Hz sine starting at its peak, my attack curve, energy above 2 kHz at
  onset): 0 ms −26.1 dB (= a hard step), 0.25 ms −34.2, 0.5 ms −40.9, **1 ms −46.2**, 2 ms −52.3, 5 ms −60.4.
  L1.1's reference for a bare sine starting at zero was −43.7 dB, so **1 ms is the shortest attack that's
  cleaner than no envelope at all**. That became the floor for every segment.
- Release (T60 definition) should land at exactly releaseMs at any sample rate, and reach zero at
  1.1115 × releaseMs (from ln(r/(1+r)) / ln(2r/(1+r)) with r = 0.001).

## What actually happened
- **Tests:** 46/46 (8 new): idle behaviour; attack, decay and release timing at 44.1/48/96 kHz (±1 sample);
  decay lands exactly on sustain; note-off during attack (monotonic, no step > 0.01); retrigger mid-release
  (continues from the current level and arrives sooner); zero, negative and NaN times (clamped, finite);
  sustain change glides; random fuzz (2000 blocks of random params and gates, output always in [0, 1]).
- **Timing** (`fss_render l1.3`): −60 dB after **500.00 ms** at 44.1, 48 and 96 kHz; idle at 555.76 ms
  (= 1.1115 × 500 ✓).
- **Clicks**, energy above 2 kHz (`click_meter.py`; lower is cleaner; steady-tone floor ≈ −102 dB):

| render | note-on | note-off | comment |
|---|---|---|---|
| gate_hard (no envelope) | −26.1 | −26.2 | the reference click |
| organ (A 5, R 10 ms) | −60.4 | −56.2 | a short soft "key" transient, 30 dB below a click |
| pad (A 800, R 1500) | −104.5 | −99.4 | at the floor: inaudible |
| pluck (A 1 ms) | −46.2 | (already silent) | exactly the predicted 1 ms value |

**Exit criteria:** no clicks at note-on/off ✅ (every seam below −43.7 dB, the cleanest envelope-free
start, and 20–75 dB below the hard gate; see `renders/l1.3_organ_off.zoom.png`); tests for
release-from-attack, retrigger, zero-time ✅; times correct at 44.1 and 96 kHz ✅.

## How it works
```
noteOn ─► Attack: level = aB + level·aC  (aims at 1.3) ── ≥1 ─► Decay: aims at S−0.001 ── ≤S ─► Sustain (glides to S)
noteOff from ANY stage ─► Release: aims at −0.001 ── ≤0 ─► Idle (isActive() = false: voice can be freed)
noteOn from Release/Decay/Sustain ─► Attack from the current level
```
Each stage is one multiply-add toward an *overshoot* target. Coefficients come from the definitions:
attack c = (r/(1+r))^(1/N) so it arrives at 1.0 in N samples; falls c = (2r/(1+r))^(1/N) so a full-scale
fall is at r = 0.001 (−60 dB) after N samples. They're recomputed in `prepare()` and `setParams()`, never per sample.

- `tests/test_adsr.cpp`.
- `tools/render/l1_3.cpp`: the three patches as audio and as plain envelopes, a hard-gate reference, the timing table.
- `tools/analyze/click_meter.py`: new `--at SECONDS` to measure a seam anywhere (e.g. at note-off).

## Alternatives rejected
- **Linear segments.** Easy to define and test, but a linear fade spends most of its time in the
  loud range and then drops off a cliff in dB. Exponential falls are straight lines in dB.
- **"Time to reach zero" as the definition.** An exponential never reaches zero, so the overshoot decides
  when it does, which makes the number arbitrary. "Time to −60 dB" is the same convention as reverb RT60 and
  is what you hear as "gone".
- **Release always takes releaseMs from any level** (time semantics). Analog envelopes don't behave that way, and a
  short note released at a low level would then fade suspiciously slowly. Rate semantics: lower start, shorter release.
- **Retrigger from zero.** Clicks if the note is still sounding. From the current level is click-free, and
  the voice-level choice (legato, same-key retrigger) belongs to L1.7/L2.5.
- **`float` state.** Measured reasoning in the header: long releases at high rates need coefficients closer
  to 1 than float can express precisely.
- **`std::max(ms, kMin)` for clamping.** Lets NaN through. The test with `decayMs = NaN` caught it before it shipped.

## What surprised me
1. **The clamp bug.** `std::max(NaN, 1.0)` returns NaN, because the comparison `NaN < 1` is false. My first version would
   have turned one bad parameter into a voice that outputs NaN forever. Fixed with `(ms >= min) ? ms : min`.
2. **Raising sustain mid-decay would click.** The natural "if (level <= sustain) level = sustain" snaps *up* if
   the knob moved above the current level. Now the decay only snaps when it crossed from above, otherwise
   the Sustain stage glides.
3. A 1 ms attack is still a measurable transient (−46 dB), and that's fine. For plucks it *is* the
   pluck. The goal isn't zero high-frequency energy, it's no *unintended* discontinuities.

## [THINK] answers
- **A = 0 ms: click? Should 0 mean zero?** Yes, it clicks: measured −26 dB, identical to a hard gate. CFS
  treats 0 as 1 ms, the shortest attack measured to be cleaner than starting a bare sine at zero. Many
  synths do something similar (DX7 rates have a finite maximum too).
- **Sustain 0.5: linear or −6 dB?** In the DSP it's linear amplitude (0.5 = −6 dB), because that's what
  multiplies the signal. The *user* of the knob is a musician, though, so in L2.4 the parameter table can map the knob
  with a skew (or display dB) without the envelope knowing.

## Decisions made
- **D6** (decided): ADSR with exponential overshoot segments, T60 rate definition for decay/release,
  linear sustain, 1 ms minimum, retrigger from the current level. Full entry in DECISIONS.md.
