# L4.4: Unison, detune & stereo (CFS)
*Date started / finished:* 2026-11-18 / 2026-11-18  ·  *Built by:* Claude

## Goal
Width and thickness: every voice can run 1–8 detuned copies of its FM core, spread across the stereo field,
with the count changeable while playing. Voices become stereo; the mod matrix gets a Pan destination.

## Design (before code)
- **What is copied:** the FM core (4 operators and their envelopes), not the whole voice. The filter, LFO 1 and
  the mod sources stay one per voice; the filter becomes a stereo pair (one SVF per channel).
- **Spread:** copies sit at evenly spaced positions −1..1; position × ½ detune = cents, position × width = pan.
  Inner positions go to the first copies, so copy 0 stays nearest the centre as the count changes.
- **Pan law:** √2·(cos θ, sin θ), θ = (1 + pan)·π/4: constant power, and unity at the centre, so one centred
  copy has the old mono level.
- **Level:** copies with random start phases are uncorrelated, so they're normalized by power (1/√Σg²), like the
  L5.4 chorus voices.
- **Changing the count while playing:** a new copy starts as a clone of copy 0 (same envelope state), with
  its own random phases, and fades in over 20 ms; detune and pan glide to their new positions; a removed copy
  fades out, then stops costing CPU.
- **Unison 1 is the old voice**: copy 0, centred, no detune, gain 1 takes the old mono path, bit-identical (the
  L4.1 golden test must stay green).
- **Phase:** copy 0 keeps the deterministic phase 0 (renders reproduce); copies 1..7 start at random phases (from
  the note counter, so renders still reproduce).

## Predictions
1. **CPU** grows linearly: N copies ≈ N × the FM core plus a fixed rest. From L4.1's numbers (FM core
   ~9 µs per voice-block, the rest ~12 µs): unison 4 ≈ 2.2×, unison 8 ≈ 4× the per-voice cost of unison 1.
2. **Mono compatibility:** with 4 copies, 20 cents, width 100 %, the mono sum (L+R)/2 is **about 1–2 dB**
   below the per-channel level (constant-power panning: a hard-panned copy contributes half its power to mono,
   a centred one all of it), with no deep comb notches, because the copies drift apart in phase.
3. **Beating:** 20 cents total spread at A3 (220 Hz) makes the outer copies beat at 220·(2^(20/1200) − 1)
   ≈ **2.6 Hz**: a slow chorus-like shimmer, not a wobble.
4. **Count changes without clicks:** a sine voice switched 1 → 4 → 2 → 8 while holding a note never steps more
   than the waveform's own slope allows (the same "max step" test as the chorus voices).

## What actually happened
1. **CPU: wrong, steeper than predicted.** 16 voices of the FM pad (which has vibrato), median µs per
   256-sample block (`fss_render l4.4`):

   | unison | µs/block | × unison 1 | % of one core |
   |---|---|---|---|
   | 1 | 378 | 1.0 | 7.1 |
   | 2 | 665 | 1.76 | 12.5 |
   | 4 | 1134 | 3.0 | 21.3 |
   | 8 | 2013 | 5.3 | 37.7 |

   I expected 2.2× and 4× (copies multiply only the FM core). But each copy also redoes its pitch maths every
   sample while the vibrato moves it (a `pow2` and four `setFrequency` per copy: the most expensive thing in
   the voice since L2.6), and the stereo path adds a second filter. It's still linear, just with a bigger slope.
   16 notes × 8 copies stays inside the budget, but it's the most expensive feature CFS has.
2. **Mono compatibility: right.** "Wide pad" (4 copies, 18 cents), a held chord, seconds 1–3:

   | width | per channel | mono sum | side | mono − channel |
   |---|---|---|---|---|
   | 0 % | −18.81 dB | −18.81 dB | (none) | 0.00 dB |
   | 50 % | −18.85 dB | −19.23 dB | −29.6 dB | −0.38 dB |
   | 100 % | −18.93 dB | −20.46 dB | −24.2 dB | **−1.53 dB** |

   Width barely changes the per-channel level (the √2 constant-power law with power-normalized copies), and full
   width costs 1.5 dB in mono, with no deep cancellation: the copies drift in phase, so no comb stays put. The
   unit test checks the same on a three-note chord (mono > channel − 3 dB, and the side is really there).
3. **Beating:** not measured separately; 18 cents at 220 Hz is 2.3 Hz between the outer copies, and that's
   the slow shimmer `l4.4_pad_unison4.wav` has. With 8 copies the inner pairs beat slower, which reads as
   "thicker", not "faster".
4. **Count changes: right.** A 220 Hz sine note going 1 → 4 → 2 → 8 → 1 copies and then to 80 cents of detune
   never steps by more than 0.02 per sample (a copy appearing at full level would step by up to ~0.25), and it
   is exactly mono again after returning to 1 copy. On the pad (`l4.4_count_change.wav`, a change every 2 s),
   the click meter at the changes reads −52 to −75 dB, no higher than between them (−47 to −65 dB).
5. **Unison 1 is bit-identical**: the L4.1 golden test (all 12 old presets) still passes in Debug and Release,
   and `l1.7_piece.wav` keeps `93d602f0…`.
6. **Tests 197/197** in Debug and Release (5 new: layout, mono vs stereo level, click-free count changes, mono
   compatibility, Engine block-size invariance with unison, count/width changes and matrix pan). Real-time audit
   0 allocations; clap-validator 34/34.

**Exit criteria.**
- A wide pad that survives mono summing ✅ factory preset 13 "Wide pad": −1.5 dB in mono at full width, no
  cancellation. (Listening in mono is the owner's.)
- Unison count changeable while playing without clicks ✅ (test and render above).
- Not done: the curriculum's **supersaw** needs saw carriers from L4.2, which isn't built yet (route order);
  the wide FM bell is a one-knob experiment on the Bell preset (below).

## How it works
- **`synth/voice.h`**: the voice holds 8 `FmVoice` copies (copy 0 is the voice of before), a smoothed gain,
  detune and pan per copy, and a second SVF. `unisonPosition(k, n)` places the copies, inner first. At note
  start every running copy starts the note, copies ≥ 1 at random operator phases (seeded from the note counter).
  Per sample:
  - **mono path** (one copy, centred, no matrix pan): exactly the old code; L = R.
  - **stereo path**: each copy ticks with its own pitch offset (detune), its output is panned with
    √2·(cos θ, sin θ) (gains cached, recomputed only while the pan moves), summed, normalized by
    1/√Σg², then filtered by two SVFs sharing one set of coefficients (`Svf::setFrom`: one `tan`).
  - **count changes** (`refreshUnison`): new copies are clones of copy 0 (same envelope state, new random
    phases) fading in over 20 ms; removed ones fade out and stop running; positions glide. When the voice is back
    to one centred copy, smoothers snap and it returns to the mono path.
- **Engine**: sums L and R separately (a mono voice adds the same value to both, so old patches give the same
  bits as before).
- **Params**: 60 Unison (1–8), 61 Unison detune (cents, outer to outer), 62 Unison width (%). Matrix: a **Pan**
  destination (±1, on top of the unison spread). Editor: a Unison section under Voice on the Synth page.

## Alternatives rejected
- **Copying the whole voice** (filter, LFOs, envelopes per copy): more CPU, and per-copy filters would make the
  copies drift apart in brightness too. The classic designs (JP-8000, Serum) copy the oscillators.
- **Positions k/(N−1) in order** (copy 0 at −1): changing the count would move copy 0, the copy that's always
  running, across the whole stereo field. Inner-first keeps it near the centre.
- **A plain sin/cos pan law** (centre = −3 dB): then unison 1 centred would be 3 dB quieter than the old mono
  voice, or the mono path and the stereo path would differ by 3 dB at the switch. The √2 scaling makes a centred
  copy exactly unity.
- **Normalizing by 1/N** (amplitude): copies at random phases add as powers, so 1/N makes 8 copies 9 dB quieter
  than one. 1/√N keeps the level (measured: within 1.5 dB per channel, unit test).
- **JP-8000-style uneven detune curve**: one function to swap in (`unisonPosition` → a curved spacing); kept
  linear for now (experiment 2).

## What surprised me
1. **The cost per copy is mostly pitch maths, not FM.** With vibrato on, every copy recomputes four operator
   frequencies per sample. An optimization for later: compute the pitch ratio once per voice and multiply each
   copy's constant detune ratio in, instead of a `pow2` per copy.
2. **The mono/stereo switch needed a filter hand-over** (`svfR_ = svf_` when the voice becomes stereo), or the
   right channel would start from an empty filter: a click on the very first unison change.
