# L2.5: Playing it like an instrument (CFS)
*Date started / finished:* 2026-11-17 / 2026-11-17  ·  *Built by:* Claude

## Goal
Make CFS *feel* like an instrument: poly / mono / legato voice modes with a held-note stack and note
priority, portamento, the sustain pedal, smoothed pitch bend, and stealing that knows about the pedal.

## Predictions (before building)
1. **Legato** (mono, overlapping notes) keeps one voice and never restarts its envelopes: a scenario test can
   see the same voice (same age) change key. Releasing the top note falls back to the previous held note
   (last-note priority), and releasing the last one releases the voice.
2. **Glide, constant time:** a 100 ms glide from C4 to C5 is linear in semitones, so the pitch is ~F#4
   (+6 st, ×√2 in Hz) after 50 ms and exactly C5 after 100 ms, whatever the interval.
3. **Sustain pedal:** a note released with the pedal down keeps sounding (still busy, not released) until the
   pedal comes up; a sustained voice is stolen before any held one.
4. **Bend as a pitch offset** (instead of baked into the base frequency) leaves every bend-free render
   bit-identical (`l1.7_piece.wav`), and smoothing a 7-bit bend staircase removes its steps.
5. **No stuck notes:** a long random sequence of notes, pedal presses and mode switches, followed by "all keys
   up, pedal up", ends with every voice free after the longest release.

## What actually happened
Scenario tests in `tests/test_play.cpp` (9 new test cases), renders from `fss_render l2.5`.

1. **Legato ✅** exactly as predicted: same `Voice*`, same age, key 60 → 64 → back to 60 → released; a
   detached note afterwards starts a new voice. **Mono (retrigger)** starts a new voice per key and fades the
   old one (5 ms, D8). **Priority** low/high hold the right note while others are pressed and fall back correctly.
2. **Glide ✅:** C4 → C5 in 100 ms measures C4·√2 (F#4) within 2 % around 50 ms and C5 within 0.01 % after;
   C3 → C5 (two octaves) is one octave up at 50 ms: constant *time*, linear in semitones.
3. **Pedal ✅:** keys released under the pedal stay busy, not released, flagged `sustained`; pedal-up releases
   them but not a key still held; re-striking a sustained key fades the old voice and starts a held one.
   **Stealing** with 3 voices: the pedal-only voice is taken, not the oldest held one. In the chord render,
   1.0 s into each bar: −29.0 dB with the pedal, silence (−300) without (keys held only 150 ms).
4. **Bend:** `l1.7_piece.wav` still `92baa60b…` ✅. The smoothing part was **wrong in an interesting way**: a
   7-bit, 60 Hz bend staircase on a pure 440 Hz sine puts almost nothing above 4 kHz either way (−118.1 dB
   unsmoothed, −122.4 dB smoothed). Phase is continuous, so a pitch *step* is a kink in the waveform's
   slope, not a jump in its value. What the 3 ms smoothing removes is the audible *stepping* of pitch (a
   fast staircase glissando), not clicks. Same lesson as the cutoff in L1.10.
5. **No stuck notes ✅:** 3000 random events per mode (notes, pedal, bends, and voice-mode switches in the middle),
   then all keys up and pedal up: 0 busy voices 200 ms later, in poly, mono and legato.
6. **Voice modes in the renders** (centroid from `brightness.py`): legato bass glides 155 → 216 Hz smoothly across
   a note change; the same line in mono re-attacks (centroid jumps to 527 Hz at each new note); poly lets the
   overlaps ring together.
7. **Tests 128/128** in Debug and Release; the real-time audit (random params now include voice mode, glide,
   priority) still counts 0 allocations; block-size invariance still bit-exact.

**Exit criteria.** Scenario tests for legato, pedal and stealing ✅. "A mono legato bass line and
pedal-sustained chords played live, with no stuck notes": rendered and fuzzed here; **playing them live on the
keyboard is for the owner** (try the Legato bass preset and the Sustain checkbox / CC 64 in fss_play).

## How it works
- `core/include/fss/synth/held_notes.h`: `HeldNotes`, a fixed-capacity (16) press-ordered list; `pick()` applies
  last / low / high priority. No allocation.
- `Engine::noteOn/noteOff` keep the list in every mode. **Poly**: a voice per key (glide from the last
  note's pitch if on). **Mono/Legato**: `monoUpdate()` runs after every change of the held set and makes the one
  sounding note agree with `held_.pick(priority)`: legato moves the same voice (`Voice::legatoTo`: new key,
  envelopes untouched, pitch continues and glides); mono starts a fresh voice and fades the old one.
- **Glide** (`Voice::glideFrom`): an offset in semitones that steps linearly to 0 in exactly `glideMs`.
- **Pitch** now meets in one place per sample: `bend + glide + vibrato` semitones → `FmVoice::setPitchOffset`.
  Bend left the base frequency: it's smoothed (3 ms) in the Engine and travels in `VoiceControl`.
- **Sustain pedal** = `Controller` CC 64 (≥ 64/127 = down). Poly note-off under the pedal → `Voice::sustain()`;
  pedal-up releases every sustained voice; mono keeps its gate while the pedal is down.
- **Stealing (D8 refined):** released → pedal-only → held, oldest first within each rank.
- 4 parameters (ids 50–53, group "Voice"): Voice mode, Glide (ms, **CC 5** = MIDI's portamento time), Glide
  legato (only glide between connected notes), Priority. fss_play gained pitch-bend (springs back) and a
  sustain checkbox; preset **Legato bass**.

## Alternatives rejected
- **Restarting the voice in place for mono retrigger** (reset envelopes, keep the slot): resets the phases
  mid-waveform, which clicks. A fresh voice + the 5 ms steal fade (D8) is click-free and reuses existing code.
- **Glide as an RC lag (exponential)**, like an analog portamento circuit: "glide time" then has no exact end
  (it approaches forever) and big intervals *sound* faster at the start. Constant-time linear-in-semitones
  makes the parameter mean exactly what it says. Constant *rate* (ms per octave) is the other common choice.
- **Bend baked into each voice's base frequency** (as through L2.4): every bend message cost 4 `exp2` per
  voice, and smoothing it would cost that per sample. As an offset it joins vibrato and glide for free.
- **Mapping poly voices onto mono on a mode switch**: no musical answer; release and start clean instead.
- **MPE / per-note expression**: optional in the curriculum; it belongs with CLAP's note expressions (L3.2).

## What surprised me
1. **Pitch steps don't click either** (see 4.). With phase-continuous oscillators, the only discontinuities are
   in the *slope*, whose spectrum falls fast. Smoothing is for the ear's sense of pitch movement.
2. **The held-note list is needed even in poly mode**: "glide only between connected notes" asks "is another
   key down?", and the pedal logic needs to tell "key up" from "voice released".
3. **My first glide test failed on the test, not the synth**: a 4 ms window holds only one zero crossing at
   370 Hz, so it measured 0 Hz. Widened to 10 ms.

## [THINK] Which behaviours should be parameters, which fixed design choices?
**Parameters** (the player or sound designer chooses per patch): voice mode, glide time, glide legato-only,
note priority, bend range (since L2.4). **Fixed** (choices about how the instrument *works*, not how it sounds):
pedal semantics (MIDI's), steal ranking (released → pedal → held), same-key re-strike, the 5 ms steal fade,
constant-time glide shape, the 3 ms bend smoothing, mono retrigger via a fresh voice. Any of the fixed ones
could become a parameter later if a sound needs it (constant-rate glide is the most likely), but each one
added is one more thing a preset must store and a player must understand.

## Decisions made
- **D8 refined** (Log entry, 2026-11-17): steal ranking released → pedal-sustained → held; mono retrigger reuses
  the fade-slot mechanism.

## Experiments to try
1. fss_play → **Legato bass**: hold a note, play others on top (legato slides), then play detached notes (no
   glide, since Glide legato is on). Turn Glide legato off: now every note glides.
2. Switch Voice mode to 1 (mono retrigger) on the same preset, and Priority to 1 (lowest): hold a low note
   and trill above it.
