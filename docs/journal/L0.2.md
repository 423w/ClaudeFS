**Aliasing (THINK #3, predicted before rendering).** A naive 5 kHz saw at fs = 48 kHz, amplitude 0.5:
harmonic *k* sits at 5k·*k* with amplitude 1/(π*k*). Anything above 24 kHz folds: f → 48k − f (or f − 48k,
then fold again). Since gcd(5000, 48000) = 1000, the folded partials land on *every* multiple of 1 kHz,
most of them **inharmonic**: they're not multiples of 5 kHz, so the ear hears them as dissonant junk.

## How it works

Pitch and loudness are exponential in the physics and linear in the ear, so the helpers are just
`exp2`/`log2` (pitch: octaves are powers of 2) and `pow(10, ·)`/`log10` (loudness: dB is a decade scale).
See the header comment in [math.h](../../core/include/fss/util/math.h) for the formulas.

**Aliasing, drawn.** Sampling can't tell f apart from fs − f (or fs + f):

```
 the first 8 samples (fs = 48 kHz), exact:

   n                       0     1      2     3      4     5      6     7
   sin(2π·30k·n/48k)       0  −0.707   1   −0.707    0  +0.707  −1  +0.707    (phase steps 225° per sample)
  −sin(2π·18k·n/48k)       0  −0.707   1   −0.707    0  +0.707  −1  +0.707    (phase steps 135° per sample)

 identical samples. A 225° step forward lands where a 135° step backward does (225 = 360 − 135),
 and the DAC rebuilds the smoothest curve through these dots: the 18 kHz one.

 the frequency axis folds like paper at Nyquist (fs/2):

  0 ─────────────── 18k ─── 24k ─── 30k ───────── 48k
                     ▲       │       │
                     └───────┘◄──────┘   30k is 6k above Nyquist → lands 6k below it
```

Rule: a component at f appears at |f − m·fs| for whichever integer m puts it in [0, fs/2].

## Alternatives rejected
- **`constexpr` helpers** (what the curriculum asks for). In C++20, `std::exp2`, `std::pow`, `std::log10`
  aren't constexpr, so a `constexpr` function calling them can never run at compile time, and a
  `constexpr` variable initialized from one is a compile error. I could hand-write constexpr series
  for exp/log, but that's a precision project, not L0.2. They're `inline` with a comment saying when
  to flip them.
- **`double` everywhere.** These run per note or per block, not per sample, so the precision of `float`
  (≈7 digits; round trips accurate to 0.01 cents) is plenty, and it matches CFS's sample type. Phase is
  where `double` matters (D5, L1.2), and this lesson found a live demo of that (see "surprised").
- **`gainToDb(0)` → `-inf`.** Honest, but a −∞ that leaks into later math (smoothing, meters) becomes NaN.
  I clamp to `kSilenceDb` = −144 dB (≈ 24-bit noise floor) instead, and test for it.
- **Only a `dbToGain` with `exp(db · ln10/20)`.** That's faster than `pow`, but less readable. Swap it in
  if a profile ever asks (L2.6).

## What surprised me
1. **Float rounding broke my naive test saw.** The first version computed the phase as
   `(5000.0 * t) % 1.0`. At 56 of the 1000 wrap points, `5000·n/48000` came out as 4.999… instead of 5,
   so the sample landed at the *top* of the ramp instead of the bottom: a full-scale error. The spectrum
   showed a noise floor at −55…−80 dB that shouldn't exist (a periodic signal on exact bins has no
   leakage). Computing the phase with integers removed it completely. That's D5 (L1.2) showing up early:
   **phase precision matters exactly at the wrap, where tiny errors become huge ones.**
2. **Non-ASCII test names fail on Windows.** `"note → Hz → note"` compiled and ran fine standalone, but
   under CTest it "failed" with *No test cases matched*. `catch_discover_tests` passes the name back as a
   command-line filter, and the ANSI code page mangles `→` and `−` on the way. Test names are ASCII now
   (comment in test_math.cpp).
3. How large the aliases are. A naive saw's 2 kHz alias at −29 dB sits only ~20 dB under the
   fundamental. That's easily audible. L1.8 (PolyBLEP) isn't optional polish.

## [THINK] answers
1. **30 kHz at fs = 48 kHz:** 18 kHz. It's 6 kHz above Nyquist (24 kHz), and folds to 6 kHz below it.
   Equivalently, the samples of sin(2π·30k·n/48k) equal those of −sin(2π·18k·n/48k) (same frequency,
   inverted phase).
2. **Why cutoff and envelope-time knobs feel logarithmic:** we hear *ratios*, not differences. 100 → 200 Hz
   sounds like the same step as 1 k → 2 kHz (an octave each), so a knob that's linear in Hz would cram all
   the musically useful low range into its first few degrees. Times are the same: 1 ms vs 2 ms is a big
   difference, 1001 ms vs 1002 ms is none. So the knob is linear in log(Hz) or log(ms).
3. **5 kHz saw at fs = 48 kHz:** 5, 10, 15, 20 kHz are real; 25 → 23k, 30 → 18k, 35 → 13k, 40 → 8k, 45 → 3k,
   50 → 2k, 55 → 7k, … and they keep folding back and forth forever, landing on every 1 kHz multiple.
   Measured above.
